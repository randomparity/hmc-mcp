# ty 0.0.74 — design

#596: move the `dev`-group ty pin `0.0.62` → `0.0.74` alone, superseding the ty part of PR #418.

## Requirements

1. `pyproject.toml`'s `dev` group pins `ty==0.0.74`, `uv.lock` matches, and no other package
   moves in the lock — independence is the point of the issue.
2. `TOOL_PINS` in `tests/test_ci_pipeline.py` carries `ty==0.0.74`.
3. `just typecheck` exits 0 on 3.11–3.14, amd64 and arm64. `ty check --python-version` gives the
   identical single diagnostic for all four, and `uv.lock` resolves one version per package, so
   the open axis is the runner architecture and interpreter build — hence the eight-leg matrix.
4. `just verify` and `uv run --no-sync prek run --all-files` are green.

## Diagnostic delta (measured, not predicted)

`uvx ty@0.0.74 check` in the worktree at `3d013e76`, against the `just setup` venv, reports one
diagnostic where 0.0.62 reports none, and exits 1 on it:

    warning[unused-ignore-comment]: Unused `ty: ignore` directive
      --> src/hmc_mcp/config.py:788:57

0.0.74 no longer raises `unknown-argument` for `HMCConfig(_env_file=None, **filtered_entry)`, so
that line's directive suppresses nothing. **Decision: delete it** — the diagnostic is valid, so
the fix belongs in source, with no configuration and no new suppression. The `_env_file=None`
argument itself stays: ADR 0096 decided that deliberately, so it is settled, not deferred.

## Threat model

Security-relevant only as a dependency change; it adds no trust boundary and widens none. The
boundary is the `dev` group's supply chain: PyPI and ty's publisher, against a workstation and a
CI runner, where `ty` runs at check time with their privileges and ships in no wheel. The lock's
hashes and `tests/test_supply_chain.py`'s pin check govern later installs; this first fetch is
governed by Dependabot's reviewed 7-day cooldown, which a manual bump bypasses — 0.0.74 was
published 2026-08-22, eleven days ago. Out of scope: other `dev` pins (ty locks no dependencies).

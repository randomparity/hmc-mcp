# Plan — ty 0.0.74 (#596)

**Goal**: move the `dev`-group ty pin to `0.0.74` and clear the one diagnostic it raises.
**Architecture**: a pin move across three declaration files plus one source line, with no code
path change; `just typecheck` keeps covering `[tool.ty.src] include = ["src/hmc_mcp"]`. Spec:
`docs/workflow/specs/2026-09-02-ty-0-0-74-design.md`.

**Global Constraints.** Python floor 3.11; targets 3.11–3.14 on amd64 and arm64. Dev tools are
exactly pinned; never a bare `uv sync`, `uv run`, or `uv add` — always `--no-sync`, then
`just setup`. CI pins uv 0.12.3 and just 1.58.0 (`.github/workflows/ci.yml`, asserted by
`tests/test_ci_pipeline.py`) while this host has uv 0.12.1, so every lock write goes through
`uvx uv@0.12.3`: the committed lock must be one CI's `uv sync --locked` accepts. Base:
`feat/update-ty-0-0-74-596` off `main` at `3d013e76`.

Expected implementation size: 22–26 changed lines (S) — about 20 in `uv.lock`'s generated `ty`
entry plus its specifier line, and one each in `pyproject.toml`, `tests/test_ci_pipeline.py`,
and `src/hmc_mcp/config.py`. Those four files are the whole file map; nothing is created.

## Task 1 — move the pin and clear its one diagnostic

1. `uvx uv@0.12.3 add --dev --no-sync "ty==0.0.74"`. Expect `pyproject.toml:59`
   `    "ty==0.0.74",` and `uv.lock`'s `name = "ty"` block at `version = "0.0.74"`; if the lock
   is untouched, `uvx uv@0.12.3 lock`.
2. `git --no-pager diff uv.lock`: only the `name = "ty"` entry and the dev-group `specifier`
   line may appear. Anything else — another package, or the header's `version`, `revision`, or
   `resolution-markers` — is a finding about the toolchain or environment, so stop and report
   it rather than retrying.
3. `just setup`. Expect `+ ty==0.0.74`, exit 0.
4. In `tests/test_ci_pipeline.py`, change the `TOOL_PINS` entry `"ty==0.0.62",` to
   `"ty==0.0.74",`; nothing else in that set moves. Then `uv run --no-sync pytest
   tests/test_supply_chain.py tests/test_ci_pipeline.py -q --no-cov`, which also proves the pin
   agrees with the lock — expect all passed.
5. `just typecheck`. Expect the spec's one `warning[unused-ignore-comment]` at
   `src/hmc_mcp/config.py:788`, exit 1 — observe that red first, then delete only that trailing
   directive, leaving `    return HMCConfig(_env_file=None, **filtered_entry)`.
6. `just typecheck` (expect `All checks passed!`, exit 0), then
   `for v in 3.11 3.12 3.13 3.14; do uv run --no-sync ty check --python-version $v; done`
   (expect that clean result four times), then `just verify`, then
   `uv run --no-sync prek run --all-files`. Expect green.
7. Commit as `chore(deps): update ty to 0.0.74`, its body recording that the directive at
   `config.py:788` went because 0.0.74 stopped raising `unknown-argument` there, and that
   `_env_file=None` itself stays by ADR 0096.

**Acceptance**: every spec requirement, step 2 as requirement 1's independence evidence, and no
`ty: ignore` added for the diagnostic this design measured. Requirement 3's matrix comes from
the delivery phase; a leg reporting a diagnostic the step-6 sweep cannot is a stop-and-rescope,
not a blind patch. **Hand-off**: step 3 repoints the shared `.git/hooks/pre-commit` at this
worktree's `prek`, so whenever the worktree goes away — merged or abandoned — `just setup` must
run in the main checkout, or the hook falls back to an unpinned `prek` on PATH. **Rollback**:
`git restore` the four paths, then that same `just setup`.

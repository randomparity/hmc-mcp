# CI gate orchestration measurements — issue #1431

The [design's execution map](specs/2026-10-08-ci-gates-once-design.md#execution-map)
lists the complete before/after gate set. This report measures the static portion
only; final exact-head hosted comparison is recorded in the implementing PR linked
from [issue #1431](https://github.com/randomparity/hmc-mcp/issues/1431).

## Paired local component samples

Both variants ran on clean integrated commit `bbe512ca89070945674005f43846b4893d3f1330`,
including #1433 via base `ad2f5f777b96887924c037e54ff5ed0dfcbf1e4c`.
The before sequence reconstructs the former CI static callers using these same
optimized leaf implementations; it is not a run of an older checkout or full CI.
The explicit launcher `--no-sync` preserves the former environment-controlled behavior.

Before, four separate commands in order:

```sh
just tool-docs-check
just doc-freshness
just static
env UV_NO_SYNC=1 uv run --no-sync prek run --all-files
```

After, one command:

```sh
env UV_NO_SYNC=1 uv run --no-sync prek run --all-files
```

Two pairs ran serially, before then after, with no other campaign benchmark.
Existing setup venv and uv/download/OS caches were retained, without eviction.
Python 3.11.15, uv 0.12.19, just 1.57.0, prek 0.5.0; Fedora 44 Linux 7.2.7,
x86_64, 48 visible/affinity CPUs, 250.92 GiB physical RAM and about 45.62 GiB
available. Load averages (1/5/15 minutes) went from 0.36/0.70/0.96 before pair 1
to 1.55/1.59/1.33 after pair 2. Cgroup limits were not measured; no hardware floor
or equivalence with hosted resources follows. `time.monotonic()` measured command
and route wall time. All ten real commands exited 0; HEAD and tracked bytes stayed clean.

## Negative controls and limits

The route fixture preserves real just composition and real pinned prek dispatch,
substituting recording/failing commands only for expensive leaves. It found 16
extra hosted invocations before the change. Afterwards, both routes execute their
20 intended leaves once, and each deliberately failing leaf blocks its route
(42 cases). These observations prove orchestration, not production gate runtimes.
Removing a hook or its recipe fails the correspondence guard; a broken hook entry
fails real prek before runtime execution. Separately, stale tracked generated bytes
made both real documentation recipes and both selected real hooks exit 1, naming
the file and hook identifier. Fault bytes were restored and clean hooks passed.

The hosted before sample is successful [run 37854277531](https://github.com/randomparity/hmc-mcp/actions/runs/37854277531)
at `082b9962777debebc2ef3dc762cf0c737440c09a`: 900s creation-to-final-status elapsed,
5,764 summed seconds across 19 executed jobs, and 3s until the first job started.
One conditional skipped job is excluded. The final PR comparison reports actual
elapsed and aggregate time separately, retaining queue, runner/cache variability
and the single-hosted-sample limitation. #1430's baseline is retained unchanged.

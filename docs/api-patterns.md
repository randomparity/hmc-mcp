# HMC API patterns

Every pattern on this page was observed on an HMC at V10R3 managing POWER9 hardware. None of
them says anything about other HMC releases or other hardware families. Each `path:line`
citation was read at the branch base commit `11d3d9dd`; line numbers drift as `main` moves.

The patterns come from the live capture windows recorded on issue #1161 (P1 to P47) and from
four observations made during the #879 live window (N1 to N4). Each row links the issue comment
it restates. Identifiers are tokenized the way the comments tokenize them: `sys-R1` for the
managed system, `<UUID>`, `<S>` and `<L>` for system and partition UUIDs, `{JobID}` for a job.

Columns:

- **Captured**: the commit the capture ran at, as its comment states. Comments for P28 to P47
  name no commit, so they read "not stated"; all of them are dated 2026-09-30.
- **Code paths**: where hmcpctl handles the pattern, and whether that code conforms to it or
  diverges from it. "No code path handles this" means a search of `src/hmcpctl/` found none.
  "Not determined" means the search could not settle the question.
- **Fix**: the issue or pull request that changed the code to conform, or "—".

## Capture harness

`scripts/live_test/capture.py` records what hmcpctl sends to and receives from a live HMC, so
a new pattern can be captured instead of guessed. A probe script wraps its calls in
`capture(path)` and labels phases with `step(name)`. Every REST request
(`HMCClient._request`) and SSH command (`asyncssh.SSHClientConnection.run`) becomes one JSON
line. The harness refuses a destination git does not ignore (use a name ending in
`.capture.jsonl` or a path under `hmc-captures/`), writes the file with mode 0600 (tightening an existing file), drops
session and cookie headers, redacts the session values an HMC error body echoes, and replaces
logon exchanges and text naming a secret before writing. Hostnames, UUIDs and serials are recorded as-is, so a capture is private and is never
pasted into a public issue or committed.

A live run follows [live testing](live-testing.md): preflight first, one arm through its named
script, and recovery afterwards.

## Fixture citation rule

#1161 proposes that any new or changed HMC-shaped test fixture cite a capture: the window or
comment whose observed response it reproduces. This is not yet enforced by any gate; it is a
review convention until a check exists.
